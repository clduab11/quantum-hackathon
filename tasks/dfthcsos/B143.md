# (8, 143, 60) chemistry through the full-XOR J=5 compiler (PRA-321)

`tasks.dfthcsos.b143` generates 15 exact five-word ANGLE circuits from SomeJoint's
published factor (`qcc-our-chemistry-b143-c60-xor2` version 1, R=8, B=143, C=60,
8-bit words). It copies the declared non-circuit NPZ unchanged. No circuit,
decomposition certificate or audit is an input. The plan and schedule for each
circuit are committed in `tasks/dfthcsos/full_xor/plans.json` and replayed by the
ported emitter. Source versions, URLs, hashes and licence observations are in
`ledger/manifests/inputs/pra309-chem-8-143-60.json` and `notices/30-dfthcsos.txt`.

The dataset does not contain the compiler. It publishes `submission.npz` and `BUILD.json` only. The full-XOR compiler is notebook `somejoint/quantum-circuits-22-67-local-gm-full-xor-chem` version 18. Both are pinned because neither publication carries the factor and the compiler together.

## Prerequisites and use

Run `uv sync`, then install the organizer Kickmix/verifier paths with
`uv run python scripts/install_kickmix.py /home/cld-main/work/vqcc-data/google-verifiable-quantum-circuit-compilation`.
Place version 1's `submission.npz` at
`inputs/somejoint/qcc-our-chemistry-b143-c60-xor2-v1/submission.npz` under
`VQCC_DATA` (default: the package root above). The generator pins its hash.

```sh
uv run python -m tasks.dfthcsos.b143 --help
uv run python -m tasks.dfthcsos.b143 --data /home/cld-main/work/vqcc-data --out /tmp/pra321-build --dry-run
uv run python -m tasks.dfthcsos.b143 --data /home/cld-main/work/vqcc-data --out /tmp/pra321-build
OPENBLAS_NUM_THREADS=1 uv run pytest -q tests/test_b143_compiler.py
```

Dry run validates the hash and compiles in memory without writing files. A
normal build writes only `OUT/dfthcsos/submission.npz` and `angle_k_0..14.kmb`,
and prints file hashes and resource counts as JSON. A hash mismatch, a plan
that does not reproduce its recorded circuit, or a nonempty output directory
raises an error and exits nonzero. G5 supplies its isolated data root through
`VQCC_DATA`. No download, GPU work or submission occurs here.

## Exact construction

Batches are five words (75 angles → 15 circuits). Split the 11 selection bits
into four low and seven high bits. Each output bit is an XOR of products of
address bits. One Toffoli computes the AND of two XOR combinations and covers
two products. The committed plan names those products. The committed schedule
says when each low-address product is cached. High monomials stay in a
parent-closed cache. Low monomials use a six-to-eleven slot cache and are
erased by HMR plus a conditional CZ while their parents are still live. No word
qubit controls a Toffoli or is used as workspace, so the circuit is the XOR
oracle on every incoming word state.

Per circuit, from the committed plans: circuits 0–3 have no coded low bit
(225 products, 305 Toffolis, 126 qubits); circuits 4, 6, 8, 10, 12 and 14 have
one (203 / 283 / 128); circuits 5, 7, 9, 11 and 13 have two (180 / 260 / 128).
One pass is 4,218 Toffolis. The published Apache-2.0 notebook does not include
the search that chose the product basis, so the plans are replayed, not
re-searched. `tasks/dfthcsos/full_xor/paired_anf.py` still contains that
notebook's earlier exact planner; it is not what these 15 circuits use.

## The factor

The weight fit that produced `(R,B,C)=(8,143,60)` is not in the published
source. The factor is the declared non-circuit input under D-PRA211-05. The
notebook's factorization trainer is absent, so this port does not regenerate
the numbers.

## Verification and hand-off

Use `configs/gates/pra309-chem-8-143-60.yaml`: `pra294-c59.yaml` (submission-010)
with only the chemistry G1 hook, generator, input pin, shot count and G4
changed (pinned by `tests/test_b143_compiler.py`). All G0–G5 gates are
non-waivable. G3 requires 78,080 chemistry shots at the fixed public salt.
G4 keeps submission-010's checks and adds chemistry ≥ 9.7×. G5 stages only the
declared NPZ and rebuilds all circuit bytes from the generator commit.
